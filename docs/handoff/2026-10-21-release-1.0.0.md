2026-10-21 用户审核冻结后，最新要求审计清理并上传 Android 和后台源码，同时提供最新 release APK。本文件取代此前停止 APK 构建和禁止 GitHub 推送的过程说明。原签名仍待用户提供本地位置，未生成或交付新的签名 APK。

## 版本

- 版本名 `1.0.0`，versionCode `10`，包名 `com.mychuannong.app`。
- 应用名“我的川农”；未来 release APK 文件名 `my川农_chuannong_1.0.0.apk`。
- 两个现有私有仓库交付分支均为 `codex/release-1.0.0`；不重写历史、不创建二进制 Release、不部署官网或服务器。

## 原签名与服务配置

原 JKS 由用户保存在自己的电脑，不上传源码仓库。未来以 `MY_CHUANNONG_SIGNING_CONFIG` 指向仓库外签名 properties，继续核对历史证书 SHA-256：`a8f8eac6ff810cac0b21cbd59a08d5525e1aca9c225f86f516fbd1172becdf6d`。先前另建的未使用密钥已单独归档，不能替代原签名。

后台 HTTPS 服务和正式高德 Key 尚待用户部署配置：

| 配置 | 本机 local.properties | 环境变量 |
| --- | --- | --- |
| 账号 API | `campusTools.apiBaseUrl.release` | `MY_CHUANNONG_CAMPUS_TOOLS_API_BASE_URL_RELEASE` |
| 高德 Key | `amap.apiKey.release` | `AMAP_API_KEY_RELEASE` |

缺失配置时不模拟账号登录或地图成功。此前按用户要求保留的 `-PreleaseReviewWithoutServices=true` 仅供未部署服务时的本地审核构建，仍校验原签名和 HTTPS；正式联网交付应补齐配置并使用默认校验。高德 Key 需匹配原证书和正式包名，不能复用 Debug Key。

## 从对应源码构建 APK

在干净提交上配置 JDK 17、`ANDROID_HOME` 和仓库外的 `MY_CHUANNONG_SIGNING_CONFIG`。后者可参照 `signing.example.properties`，其中路径、别名和口令由用户在本机填写，勿提交或在聊天发送。

```text
python tools/build_release.py --output-dir <仓库外交付目录>
```

仅在用户已授权的“服务尚未部署、本地审核”场景追加 `--review-without-services`；版本名仍为 1.0.0，账号后台和地图不可被当成已上线功能。脚本先执行签名/服务配置校验，再构建 release，核对包名、版本、非 Debug 属性及原证书，生成 APK 和 `delivery-manifest.json`。凭据记录精确 Git SHA、源码清单摘要、构建配置摘要、APK SHA-256 和证书指纹，不记录密钥与口令。其他电脑可按凭据中的提交检出源码；仅凭相同版本名不能证明源码与 APK 一致。

脚本不会生成密钥、覆盖既有交付包或自动发布。缺少原签名时应停止，不得换成 QA 包。当前缺少 JKS，完整签名打包路径尚未实测；本轮通过的是源码检查、测试与 release 编译优化检查。

## 清理范围

保留审核冻结功能与历史提交，移除旧原型的模拟机构/预约、默认二手和失物样例、后台示例公告初始化入口；服务失败不再回退显示模拟机构。新建后台数据库仅有必要配置，不预填运营内容，版本记录为 1.0.0 草稿且更新开关关闭。

历史本地真实记录、数据库、上传文件、备份、签名材料不做批量清空，也不进入源码提交。测试使用独立的合成夹具和临时数据库，不能导入生产。
