# 双认证保持与按需自动恢复（2026-10-21）

本轮在现有 Android 工程上增量实现。保留工作区已有改动、UI 主体、学习缓存和离线启动方式；未修改产品后台，未提交、推送、发布 Release 或部署服务。只有 Android 源码，未实现或验证 iOS Keychain。

## 使用行为

1. 首次使用必须先完成官方校园 VPN / 川农 e 认证并通过教务登录页资源检查，再提交独立教务账号。两种网络选项仍保留原有名称，校园网选择也不跳过第一步。
2. 教务绑定表单新增默认不勾选的安全保存授权。只有用户主动同意且学校返回的本人学号与输入匹配，才保存教务账号密码。旧安装不会自动获得授权；需要在学校账号页重新认证并主动开启一次。
3. 学校 Cookie、原生教务会话和网页会话仍优先复用。每次在线读取先用学校本人资料 GET 确认身份并接纳学校真实返回的 Cookie 轮换。没有确认学校独立 Refresh Token 接口，因此没有编造刷新协议或延长学校会话期限。
4. 教务过期先尝试同源网页会话，再按授权执行原有官方表单认证。并发读取串行共享恢复后的会话；身份核验到业务 GET 之间过期也可恢复后续读。密码 POST 本身不重放。
5. 课表、成绩、考试均提供下拉刷新；返回最新数据后更新本地缓存和成功时间。考试页面先读缓存，更新失败继续显示列表。首页、课表和成绩页仅在恢复结束后显示必要信息，不主动打开登录页面。
6. 教务网页先准备已经验证的原生会话。学工、一网通办、统一认证和缴费沿用官方 SSO 票据衔接；代理会话与直连业务 Cookie 保持各自的作用域。需要 VPN 的页面先检查并尝试官方 CAS 恢复，然后再次验证资源。网络失败不当成密码失效。
7. 冷启动和返回前台仍不自动刷新教务。上课提醒、小组件和本地学习数据不依赖当前 VPN 在线。

## 凭据和状态边界

- `SchoolAuthState` 只描述教务认证，`UnifiedAuthState` 描述统一认证，`SicauWebVpn.phase` 描述 VPN 通路。任一过期不会自动撤销其他认证或本机已核验绑定。
- `AcademicCredentialVault` 使用独立 Android Keystore AES-GCM 密钥、AtomicFile 和 noBackupFilesDir 保存教务凭据、授权对应的账号/路线及重试计数。既有备份/设备迁移排除继续生效。数据没有普通偏好设置、日志、埋点或自有服务器写入路径。
- 登录表单和官方网页禁止系统保存输入。川农 e 密码继续由本人在官方页面输入，App 不读取其表单值；若统一认证已撤销并要求验证码或二次认证，使用官方交互。
- 关闭自动登录会删除保存的教务密码并阻止旧请求回写；解绑/退出同时清理学校会话。仍有效的学校会话可以继续复用。
- 自动密码尝试前先持久写入计数。最多两次连续未完成的尝试，间隔至少一分钟；成功后也保留冷却期，避免服务器立即撤销导致快速重新提交。错误密码、身份不符、验证码/短信、未知登录响应等停止自动提交，要求本人处理。
- Cookie 恢复等待 Chromium 写入回调。账号、授权和退出版本屏障覆盖请求、凭据 POST 和持久化；关闭绑定页面不会取消已移交给共享管理器的有效会话。
- 用户经学校网页处理密码或二次验证后，App 不保存此前失败的旧密码；如需要凭据自动恢复，应再使用当前教务密码明确开启。

## 复测命令

普通产物：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --no-configuration-cache
```

隔离设备包：

```powershell
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest '-PcacheTestSuffix=.dualauth' '-PdeviceTestBuildType=debug' --no-configuration-cache
adb install -r app/build/outputs/apk/debug/MyChuannong_debug_v0.1.0-preview.9.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -e class com.mychuannong.app.school.DualAuthDeviceTest com.mychuannong.app.dualauth.test/androidx.test.runner.AndroidJUnitRunner
```

两个跨进程测试默认跳过，分别以 `-e dualRestart seed` 和 `-e dualRestart verify` 配合对应方法执行。隔离构建后重新运行普通 `assembleDebug` 才是面向原 Debug 包的交付文件。不要清除用户原安装数据。

## 依据

- [Android Keystore 官方说明](https://developer.android.com/privacy-and-security/keystore)：密钥由系统管理，客户端使用不可导出的密钥执行加解密。
- [AndroidX SwipeRefreshLayout](https://developer.android.com/jetpack/androidx/releases/swiperefreshlayout)：XML 页面使用已发布的 1.2.0；课表继续使用现有 Material3 PullToRefreshBox。
- 学校协议沿用已经检查的本地适配和此前公开 SSO 前端证据；本轮只读打开 [官方 VPN 入口](https://webvpn.sicau.edu.cn/) 仍进入代理川农 e 页面。公开教务入口读取超时，不据此推断用户密码或学校服务状态。
